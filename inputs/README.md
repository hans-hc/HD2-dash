# Editing and reviewing inputs
The CSVs in this directory are authoritative. Curation reads them and leaves them intact. The Excel workbook is a review copy. Blank means unanswered. Review dates reflect when the owner actually recorded a judgment.

The completed study is retrospective. The hypothesis and numerical prioritization inputs below are optional review fields, not unfinished requirements or preregistered claims. The final investigation choice is documented in Confluence.

1. For an optional retrospective hypothesis, enter one per existing case ID. Set expected_direction to `increase` or `decrease`, metric to `short_term_lift_pct`, `sustained_lift_pct` or `review_change_pp`, and a nonnegative threshold magnitude in percent or percentage points. For example, a minimum lift magnitude of ten percent is entered as 10. Record an ISO date and whether results had already been seen.
2. To correct an event, use its exact ID from Events. Enter only changed fields, named reviewer, actual source URL and rationale. An accepted verification uses review_status `approved`. Original labels and dates remain in the source columns. Suggested classifications remain separate from effective classifications.
3. Enter human option ratings, final rank and approval only after review. The option matrix defines Low, Medium, High and Unknown. Final ranks and acceptance thresholds have no defaults.
4. For Excel editing, open the exported workbook, save an editable copy, edit only amber cells in Hypotheses, Event review and Prioritization, and keep all IDs. Run `python src/workbook.py --import-edits "/path/to/reviewed copy.xlsx"` before rebuilding. This explicit operation reads the three named tables, checks IDs and input file hashes, and archives changed CSVs in `inputs/archive/`. A stale copy should be reconciled manually using its stable IDs. Preserve the original workbook copy until changes are verified. Saving in Excel may change file bytes even without changing values.
5. After edits, rerun curation, data validation, analysis, workbook generation and final validation. Update narrative snapshots manually when evidence or priorities change.

## Player intake
Place a single original `steamdb*553850.csv` in raw/. Keep the header, encoding, blanks and timestamps intact. Collection registers a private immutable snapshot by SHA-256. The reviewed input is the all-history SteamDB chart with DateTime, Players and Average Players. Historical daily midnight buckets are distinguished from hourly / ten-minute samples. Read the inspection and timezone limitation in SOURCES.md. The pipeline excludes the partial UTC day.

For a replacement file, review its header, chart-day timezone, dates, benchmark, actual spacing and meaning before using the peak column. If that review confirms the same schema and UTC daily peaks, create `inputs/player_export_review.json` with the file's actual `sha256`, `daily_midnight_rows` equal to `Steam daily peaks`, and `timezone` equal to `UTC`. A file with different column names needs an explicit parser change. Monthly series, ambiguous samples and unsupported files cannot supply daily lift. The original SteamDB file and its private snapshots stay out of Git.
