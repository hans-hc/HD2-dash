# Build the two-page report
Use a supported Windows installation of Power BI Desktop. Copy the repository's curated and outputs directories to Windows. A fresh Python run also needs the private SteamDB export to regenerate player data. This kit contains source queries and a build specification. Manual assembly and Desktop verification are pending. [Desktop prerequisites](https://learn.microsoft.com/en-us/power-bi/fundamentals/desktop-get-the-desktop) · [Power BI Projects](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-overview)

1. Start a blank report. In File → Options → Current File → Data Load, turn off auto date/time and autodetect relationships after loading. In Transform data, create a blank query for each file in queries/. Paste each entire expression into Advanced Editor and give it the file's exact stem. Start with DataFolder and fxCsv, then Players, Reviews, Releases, Events, Scorecard, CaseTimeline, Date and Month. Set DataFolder to the repository's root, e.g. C:\\Data\\HD2-dash. Disable loading the parameter and function. Close & Apply and check every query has its documented types.
2. Build the six relationships in [model.md](model.md). Use cardinality 1:* and single direction, even if both sides currently have unique keys. Confirm Date and Month keys are unique. Mark Date on DateKey. Set source_url data category to Web URL. Create each measure in [measures.dax](measures.dax) separately in its relevant table. Format lift and positivity as percentages with one decimal, pp as decimal with a “pp” suffix, counts as integers with separators.
3. Import theme.json using View → Themes → Browse. Use a 16:9 canvas, dark page background #14252D, visually distinct yellow and teal lines and light high-contrast text. Title visuals in plain language. Use Insert → Text box for scope and footer. Turn off display units for scorecard counts. Use direct date columns, never automatic date hierarchies.

## Page 1 — LiveOps Overview
Place Month[MonthStart] in a Between slicer at top left, with optional Date[DateKey] Between at top right labeled “Daily visuals only.” Leave interactions enabled for Month across visuals. Disable the daily slicer's interaction with both monthly visuals. Use a card for Peak days observed and Calendar days selected to expose aggregate coverage. Include the cutoff and the date that daily peaks switch to sampled maxima from curated/coverage.json.

Place a line chart across the middle, Date[DateKey] continuous on X, Steam peak concurrent players and Peak 7-day mean on Y. Use Sampled maximum as a separately labeled third series, with a different color and a dotted line where supported. Keep blanks visible. Add a compact adjacent table of Events[date], event_name, event_type and source_url, visual-filter case_id is not blank. This accommodates multiple events on a date. For a static milestone overlay, use Analytics → X-axis constant line for each selected date where supported. The verified events table is the accessible fallback.

Place two aligned monthly visuals below: stacked columns using Month[MonthStart] and Positive reviews / Negative reviews, then a line chart with the same axis and Review positivity, 0–100%. In both use complete periods only, show no empty months. Give the line its own axis and title. State that Steam's snapshot does not provide May 2024 daily sentiment. Footer both pages with “SteamDB manual export · Steam review histogram and official Steam news · Helldivers Wiki secondary timeline · Steam only · unofficial.”

## Page 2 — Event Studies & Decision Support
Place Scorecard[event_name] in a single-select slicer, default September. Use Scorecard for the summary matrix with pre14_avg, launch_window_max, day22_35_avg, baseline_n, launch_n, later_n and activity_status. Add the lift measures, Review change pp and confounder_count. Disable subtotals and grand totals. A second table shows launch_events, later_events and assessment_reason with wrap enabled. Blank hypothesis fields indicate owner input pending.

Plot CaseTimeline[relative_day] on X with Case-day Steam peak on Y. Add vertical guides at -14, 0, 3, 22 and 35 if supported. Add phase and event_names to a companion relative-day detail table. Use a card for Prior month positivity, Event month positivity and Event month review count. Keep the selected anchor date visible. Page 1 slicers must remain page-specific. For a scatter beside the timeline use the PNG in outputs/charts/lift_comparison.png, labeled “All three cases · static on refresh.” Replace the PNG after rebuilding. The image stays intentionally independent of the case slicer.

Add cards for Case evidence note and Draft next step. An action button can link to the published evidence and proposal pages after the owner publishes them. During local review, use the relative paths confluence/02_evidence_and_event_studies.md and confluence/04_recommendation_and_measurement_plan.md in a text box; Desktop file paths are machine-specific.

## Acceptance in Desktop
Select each case and compare every card with outputs/impact_scorecard.csv. September should show +223.1% short-term and +92.1% sustained in the delivered snapshot. May has one selector entry despite two policy events. Clear the case filter and verify the lift cards go blank. Select a partial review month and confirm positivity stays blank. Choose one complete month and compare weighted positivity to the CSV. Change the daily slicer and verify monthly review volume stays fixed. Check footer, high-contrast labels and keyboard order. Save as PBIP where available, close and reopen the report, refresh it and repeat these checks. Keep local caches private. The checked-in kit has not been run in Desktop.
